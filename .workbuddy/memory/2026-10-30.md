## 翻转灯谜求解器：内核升级到 64 列 + 交互式会话

### 内核（重写为多字行）
- `bitset.ts` 引入 `Layout { h, w, words, lastMask, size }`。行宽 ≤ 32 时每行 1 字，≤ 64 时 2 字。`MAX_SIDE = 64`。
- `rules.ts` 的 `horizontalInto` 是唯一跨字进位处：左移时第 j-1 字最高位进第 j 字，右移反过来。
- `solve.ts` 增加 `SolveOptions.timeLimitMs`；`gray.ts` 的 `enumerateRange` 每 8192 次迭代查表一次，超时返回已找到的最好解。先跑 `localDescent` 拿上界，再枚举。
- 结果新增 `checked / total / timedOut`，超时一律 `FEASIBLE_UNPROVEN`。

### 踩到的两个真 bug
1. `isGoal` 用 `-1` 与 `Uint32Array` 读出的 `4294967295` 比较，**全亮目标在双字行下永远判 false**。修法：掩码结果先 `>>> 0`。
2. 测试构造器只掩了最后一行的脏位。行宽 w 时，脏位第 w 位右移会污染合法的第 w-1 位，所以「事后裁剪」不等价。构造器必须逐行掩码。

### 界面（新增状态机）
- `ui/state.ts`：`Session` 管理 盘面 / 模式 / 目标 / 阶段 / 剩余方案。
- 关键规则：每点一格 `盘面 ^= cross(x)`，同时 `方案 ^= {x}`。于是点错不是分支只是颜色（红色 = 点了但方案里还有它）。不自动重解。
- 不变量：`已点 + 还需 = 原最优 + 2 × 点错格子数`。`test/state.test.ts` 守住它。
- 时限默认 10 秒，可自定义输入（0 = 不限）。

### 实测（4096 种尺寸）
- 几何预处理均值 0.04 ms。
- d=0：2620 种；d 1..21：1456 种（1.5s 内）；d 22..24：6 种（10s 内）；d ≥ 25：14 种（超时）。
- 最坏 `61×61` d=40；`64×64` d=28。

- **卡顿根因**：「应用」不调求解器，只建 H×W 个 `<button>`（64×64 = 4096 个）；持续卡来自 `.cell:hover` 的 transform 过渡（64 列时格子 8px，指针横扫每秒上百次合成层抖动）与 `.cell.on` 的逐格 `inset` 阴影。**与算法无关**。

- 布局改为两栏：左栏 360px（标题/设置/结果卡贴底，`margin-top:auto`），右栏 `.stage` 占满高度画布；`<900px` 退回上下堆叠。页脚图例已删。

### 渲染致命 bug + 默认尺寸 + 动效（第四轮）
- **「显示全是三角形」的根因**：`roundRect` 最后一个 `arcTo` 写成 `arcTo(x+w, y, x+w, y, r)` —— 两个控制点重合，arcTo 无解、浏览器退化成直线，圆角矩形变成三角形。该 bug 从 Canvas 改写那轮就存在，肉眼一直没被发现；`rref` 无关。修法：`arcTo(x, y, x+w, y, r)`。四个拐点必须依次是右上、右下、左下、左上。
- **测试为何没抓到**：假 ctx 全是空函数，只数调用次数。补 `test/board.test.ts` 里的路径快照测试（`Stats.paths`），断言 4 个 arcTo 的控制点不重合、四个拐点落在两条竖线两条横线上且互不重复 —— 这类「形状错了但调用对了」的 bug 只能靠几何断言兜住。
- **默认视图改为固定格宽**：`fitView` → `defaultView`，`DEFAULT_CELL = 38`，棋盘装不下才收缩。5×5 不再铺满整屏。
- **动效统一到一个 rAF 流水线** `pump()`：缩放缓动（EASE .24，上限 90 帧）、悬停描边淡入淡出（HOVER_EASE .34）、标记弹入（8 帧缓出 + globalAlpha）、「应用」时从 90% 缩到 100%（SETTLE）。`paint/repaint` 里的 `writeCell` 负责判断「标记从无到有」才启动弹入，否则拖动/重绘会反复触发。
- 文案：删掉「（每个恰好 2 次）」。
- 测试 48 项全过（新增：圆角形状、标记弹入帧数、默认视图固定格宽）。

### 悬浮冻结 bug + 十字分层（第六轮）
- **「十字不跟鼠标」根因**：`setHover` 换格只调 `requestFrame()`，而 `pump()` 只有 `hoverAlpha !== hoverTarget` 才置脏——淡入落定后 alpha 恒等于 1，换格后无任何分支触发重绘，十字冻在淡入结束位置，仅在其他动画碰巧运行时跳一下。
- **修复**：拆出 `pendingOverlay` / `requestOverlay()`（仅覆盖层重绘路径）。`setHover` 改调 `requestOverlay()`；ripple / celebration / hover 淡入淡出全部只画 overlay，不再连带重画 base——64×64 上鼠标扫一排不再重画 4096 个底格。
- **十字分层**：`drawOverlay` 两遍绘制——四邻先画（1px 描边、5% 填色）、中心最后落笔（2px 描边、15% 填色），层级压在最上。`COLORS.hover/preview` 拆成 4 个语义常量。
- **测试反证纪律**：新增「跟随鼠标」回归测试后，临时把 `requestOverlay` 还原为旧 `requestFrame` 确认测试必然失败（旧逻辑 0 笔重画）再还原修复。假 canvas 增加 `paints` 记录（fill/stroke 时的 lineWidth、fillStyle、路径），层次断言（中心 2px vs 四邻 1px、最后落笔）靠它成立。
- 注意：测试选 (2,3) 这类边缘格会因十字被棋盘截断成 4 格/8 笔而误报——断言「十字完整」必须选内部格。

### 移动端手势（第七轮）
- **触屏交互模型**（`board.ts` 的 `pointers` Map + `gesture` 状态机）：
  - 单指按下 → 立即显示十字预览（`pressed` + `press` 手势），松手同格落子，滑出格子即取消——触屏没有先行 hover，靠「按下即预览」补上落点确认。
  - 第二指落下 → 整段取消正在进行的落子（`pressed=null`、`setHover(null)`），进入 `pinch`（质心锚点 + 指距比例缩放，`applyPinch` 直接落定不走缓动）。
  - 捏合中抬一根 → 退化为单指平移继续跟手（`gesture` 从 `pinch` 变 `pan`，用剩余手指位置当起点），而非整个结束。
  - 捏合手势没有 `id` 字段，`endGesture` 里 `gesture.id !== pointerId` 会直接 return——所以拆出独立的 `endTouch(event, cancelled)` 处理触屏，`pointerup/pointercancel` 按 `pointerType` 分流。
- **捏合起点漂移隐患**：单指 press 移动时若不同步 `pointers` 表，第二指落下后捏合的初始指距会用到第一指早已挪走的旧坐标。在 `pointermove` 的 press 分支里补 `pointers.set`。
- **第三指兜底**：`pointers.size >= 2` 判定（原 `=== 2`），避免第三指落下时落到单指分支重新 `cellAt` 造成混乱。
- 测试新增 4 项移动端（`test/board.test.ts`）：触屏单指落子、滑开取消、双指捏合不落子、抬一指退化平移。**59 项全过**（board 21 项）。

### 移动端触屏失效修复（第八轮，用户反馈「滑动没反应、点一下蓝一下、像图片」）
- **蓝一下**：浏览器默认 tap 高亮，加 `body`/`canvas` 的 `-webkit-tap-highlight-color: transparent`、`-webkit-touch-callout: none`、`user-select: none`。
- **手势被浏览器接管**：`.stage` 加 `touch-action: none`（原先只在 `canvas.board-canvas` 上，HUD/留白处起始的手势会被浏览器判成滚动触发 pointercancel）。这是「滑动没反应」的主因之一。
- **多指捏合失效隐患**：触屏 `pointerdown` 原在开头就 `base.setPointerCapture`，多指时浏览器对指针捕获行为不一致，会吞掉第二根手指的 move/up，捏合永远触发不了。改为触屏**不捕获**（靠 touch-action:none 让事件派发到 base），仅鼠标/触控笔捕获。
- **单指滑动改阈值区分**（用户拍板「滑动超过阈值才平移」）：`press` 手势加 `startX/startY`，`pointermove` 里触屏位移超 `TOUCH_PAN_THRESHOLD = 20px` 就从 press 升级为 pan（取消落子预览、立即按本次位移平移一次、后续跟手）；阈值内松手仍落子。pan 分支也补 `pointers.set` 保持捏合起点准确。
- **布局**：移动端 `@media` 从 `body overflow:auto + grid 68vh` 改为 `body overflow:hidden`、`.rail overflow-y:auto max-height:44vh`、`.stage min-height:0` 占满剩余——设置区独立滚动、棋盘区固定为交互区。
- **状态稳定**：结果卡 idle 不再 `display:none` 消失，改为显示「尚未求解」并 `min-height:52px` 始终占位；`#play-status` 加 `white-space:nowrap` 固定不换行，避免文案变化跳动。
- 测试新增 2 项（阈值内落子、超阈值平移），改 1 项语义。**62 项全过**（board 23 项）。
